# Общая история изменений остатков

Дата: 2026-11-17

## Цель

Добавить верхнюю вкладку «История», которая показывает последние операции с остатками всех позиций и позволяет быстро найти их по номеру макета или штрихкоду. Использовать существующие дизайн-систему, компоненты и журнал `stock_movements`; отдельный аудит изменений других полей не создавать.

## Архитектура

Реализуется первый согласованный вариант: серверный endpoint общего журнала, новый экран React и переиспользуемое поле поиска. Клиент не собирает общую историю запросами к каждой позиции.

Изменения затрагивают:

- `packages/shared`: схемы запроса и DTO общего журнала;
- `apps/server`: выборка движений с данными позиции и контрагента, поиск и пагинация;
- `apps/web`: маршрут, пункт навигации, экран истории, API-хук и общий компонент поиска;
- API-, UI- и e2e-тесты новой функциональности.

Миграция БД не нужна: `stock_movements` и индекс `stock_movements_created_at_idx` уже существуют.

## API

Добавляется `GET /api/movements` с параметрами:

- `search` — необязательная строка поиска;
- `page` — номер страницы, по умолчанию 1;
- `pageSize` — размер страницы, по умолчанию 50, максимум 200.

Ответ использует существующую структуру `Paginated`. Каждый элемент содержит поля `Movement` и вложенный объект `label` с текущими данными:

- `id`;
- `counterparty: { id, name }`;
- `layoutNumber`;
- `barcode`;
- `deletedAt`.

Возвращаются движения активных и мягко удалённых позиций. Данные позиции не копируются в журнал: отображаются её текущие номер макета, штрихкод и контрагент, связанные с движением через `labelId`.

Сортировка всегда по `createdAt DESC, id DESC`; параметров пользовательской сортировки нет. Новые операции находятся сверху.

Поиск выполняется на сервере:

- номер макета — по префиксу, с сохранением значимости ведущих нулей;
- штрихкод — по префиксу или суффиксу после существующей нормализации `normalizeBarcode`;
- контрагент и комментарий в поиск не входят;
- служебные символы `LIKE` экранируются существующим механизмом;
- поиск и пагинация применяются до формирования ответа.

Существующий `GET /api/labels/:id/movements` и история внутри карточки остаются без изменений.

## Интерфейс

В `App` добавляется пункт «История» между «Остатки» и «Удалённые». Hash-маршрутизация расширяется маршрутом `#/history`; текущие маршруты и поведение ссылок сохраняются.

Экран содержит:

1. Заголовок «История изменений».
2. Поисковое поле, визуально и по поведению соответствующее полю на главной.
3. Таблицу с колонками «Дата», «Контрагент», «№ макета», «Штрихкод», «Операция», «Изменение», «Остаток после», «Комментарий».
4. Существующую пагинацию, если страниц больше одной.

Из существующего поля главной выделяется общий компонент поиска. Он сохраняет текущие `type="search"`, классы `input input--large`, форму `role="search"`, автозаполнение и необязательную поддержку scanner target. Подпись и placeholder задаются вызывающим экраном:

- главная сохраняет текущие тексты и поддержку сканера без изменений;
- история использует подпись «Поиск по истории» и placeholder «Номер макета или штрихкод».

На вкладке истории сканирование заполняет фильтр, но не открывает карточку позиции и не меняет остаток. Глобальный обработчик сканера главного экрана на этом маршруте не активен.

Поисковый ввод обрезается по краям и отправляется с debounce 300 мс. При изменении поиска список возвращается на первую страницу. Для остатка и дельты используются существующие форматтеры; для операций — `MOVEMENT_REASON_LABELS`; пустые значения — `EMPTY_VALUE`.

Таблица использует существующие классы таблиц, числового выравнивания, прилипающего заголовка и прокрутки. Новые CSS-правила нужны только для шаблона колонок общей истории, если существующих классов недостаточно. Светлая и тёмная темы продолжают работать через текущие переменные.

## Состояния и обновление данных

Используются существующие `ErrorAlert`, индикатор загрузки, пустое состояние и `Pagination`.

- Пустой журнал: «Изменений остатка пока не было.»
- Поиск без результата: «Ничего не найдено. Измените условия поиска.»
- Ошибка сети отображается через `ErrorAlert`, включая состояние повторной попытки.
- Во время смены страницы или поиска сохраняется предыдущее содержимое через `keepPreviousData`.

Общая история входит в существующую цепочку инвалидации TanStack Query: после создания позиции, операции с остатком, заявки на перемещение/утилизацию, слияния дублей и импорта данные истории перечитываются при следующем использовании. Методы изменения остатка и существующая история карточки не меняют своей логики.

## Доступность

- Навигация остаётся обычными ссылками с `aria-current="page"`; отдельный ARIA tablist для верхней навигации не добавляется.
- На экране один видимый `h2`, поиск имеет явную подпись, таблица — caption.
- Дата представлена элементом `<time>`, изменение и остаток имеют числовое форматирование.
- Сохраняются видимый фокус, клавиатурная навигация и контраст обеих тем.
- Новая страница проходит существующую e2e-проверку axe.

## Тестирование

Добавляются или расширяются тесты в уже существующих наборах:

- shared: валидация query и DTO общего журнала;
- API: новые сверху, данные позиции, пагинация, поиск по префиксу макета и по началу/концу штрихкода, отсутствие поиска по контрагенту, история удалённой позиции, пустой результат;
- web: переход на вкладку, отображение операций, поиск с debounce и сбросом страницы, загрузка, ошибка и пустые состояния; главная сохраняет прежнее поле поиска;
- e2e: операция с остатком появляется в общей истории, поиск находит её по макету и штрихкоду, вкладка проходит axe.

Критерий готовности: `pnpm format:check`, `pnpm lint`, `pnpm typecheck`, `pnpm test` и релевантные Playwright-проверки проходят на итоговых изменениях. Реализацию пишет субагент opencode по английскому заданию; основной агент проверяет diff, тесты и пользовательский сценарий.

## Вне объёма

- Автор, время редактирования всех полей и отдельный аудит не добавляются: пользователей в системе нет, а задача ограничена действиями с остатками.
- Фильтры по операции, контрагенту и периоду, сортировка колонок и экспорт истории не добавляются.
- Денормализация номера макета, штрихкода или контрагента в `stock_movements` не выполняется.
